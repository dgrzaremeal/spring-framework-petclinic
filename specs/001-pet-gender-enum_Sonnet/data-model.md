## New Entity: Gender (Enum)

**Package**: `org.springframework.samples.petclinic.model`  
**File**: `src/main/java/org/springframework/samples/petclinic/model/Gender.java`

### Values

| Enum Constant | Display Label | DB Value (VARCHAR) | Description |
|---------------|--------------|-------------------|-------------|
| `MALE`        | "Male"        | `'MALE'`          | Biological male |
| `FEMALE`      | "Female"      | `'FEMALE'`        | Biological female |
| `UNKNOWN`     | "Unknown"     | `'UNKNOWN'`       | Gender not known or not recorded |

### Validation Rules

- Only the three constants above are valid. Any other string value MUST be rejected.
- `UNKNOWN` is the default when no value is provided.
- The enum is non-extensible for this feature (no NEUTERED, SPAYED, etc.).

### State Transitions

Not applicable — gender is a simple attribute, not a state machine.

### Proposed Implementation

```java
package org.springframework.samples.petclinic.model;

public enum Gender {
    MALE("Male"),
    FEMALE("Female"),
    UNKNOWN("Unknown");

    private final String displayName;

    Gender(String displayName) {
        this.displayName = displayName;
    }

    public String getDisplayName() {
        return displayName;
    }

    @Override
    public String toString() {
        return displayName;
    }
}
```

## Seed Data Changes

All four `data.sql` files must be updated. The `INSERT INTO pets` statements currently use positional columns `(id, name, birth_date, type_id, owner_id)`. After adding `gender`, the inserts must either:

- Use explicit column names (preferred for clarity), or
- Add `'UNKNOWN'` as the 6th positional value.

**Recommended approach** — explicit column list:

```sql
INSERT INTO pets (name, birth_date, type_id, owner_id, gender)
VALUES ('Leo', '2010-09-07', 1, 1, 'UNKNOWN');
-- ... (repeat for all 13 existing pets)
```

Alternatively, since the column has `DEFAULT 'UNKNOWN'`, the existing positional inserts can remain unchanged if the DB engine applies the default for omitted columns. However, explicit values are safer and more readable.

## JDBC Layer Changes

### JdbcPet.java

Add `gender` field for row mapping:

```java
private Gender gender = Gender.UNKNOWN;

public Gender getGender() { return gender; }
public void setGender(Gender gender) { this.gender = gender; }
```

### JdbcPetRepositoryImpl.java — createPetParameterSource

```java
private MapSqlParameterSource createPetParameterSource(Pet pet) {
    return new MapSqlParameterSource()
        .addValue("id", pet.getId())
        .addValue("name", pet.getName())
        .addValue("birth_date", pet.getBirthDate())
        .addValue("type_id", pet.getType().getId())
        .addValue("owner_id", pet.getOwner().getId())
        .addValue("gender", pet.getGender().name());  // NEW
}
```

### JdbcPetRepositoryImpl.java — UPDATE SQL

```sql
UPDATE pets
SET name=:name, birth_date=:birth_date, type_id=:type_id, owner_id=:owner_id, gender=:gender
WHERE id=:id
```

### Row Mapper (JdbcPetRowMapper or JdbcPetVisitExtractor)

When reading a `JdbcPet` from a `ResultSet`, add:

```java
String genderStr = rs.getString("gender");
pet.setGender(genderStr != null ? Gender.valueOf(genderStr) : Gender.UNKNOWN);
```
