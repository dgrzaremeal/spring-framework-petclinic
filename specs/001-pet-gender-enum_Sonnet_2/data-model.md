## New Entity: `Gender` (Java Enum)

**File**: `src/main/java/org/springframework/samples/petclinic/model/Gender.java`

| Enum Constant | DB Value | Display Label |
|---------------|----------|---------------|
| `MALE`        | `'MALE'` | `"Male"`      |
| `FEMALE`      | `'FEMALE'` | `"Female"`  |
| `UNKNOWN`     | `'UNKNOWN'` | `"Unknown"` |

**Validation rules**:
- Only these three values are valid. Any other string submitted via the form is rejected by Spring MVC's enum binding before reaching the validator (type mismatch error).
- `null` is rejected by `PetValidator` as a defensive backstop (should not occur given the field initializer).

**State transitions**: None — gender is a simple attribute with no lifecycle state machine.

**Proposed implementation**:
```java
package org.springframework.samples.petclinic.model;

public enum Gender {
    MALE, FEMALE, UNKNOWN;

    @Override
    public String toString() {
        // Capitalize first letter only: MALE → "Male"
        String name = this.name();
        return name.charAt(0) + name.substring(1).toLowerCase();
    }
}
```

## Database Schema Changes

### `pets` table — all four databases

Add column: `gender VARCHAR(20) NOT NULL DEFAULT 'UNKNOWN'`

#### H2 (`src/main/resources/db/h2/schema.sql`)
```sql
CREATE TABLE pets (
  id         INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name       VARCHAR(30),
  birth_date DATE,
  type_id    INTEGER NOT NULL,
  owner_id   INTEGER NOT NULL,
  gender     VARCHAR(20) NOT NULL DEFAULT 'UNKNOWN'   -- NEW
);
```

#### HSQLDB (`src/main/resources/db/hsqldb/schema.sql`)
```sql
CREATE TABLE pets (
  id         INTEGER IDENTITY PRIMARY KEY,
  name       VARCHAR(30),
  birth_date DATE,
  type_id    INTEGER NOT NULL,
  owner_id   INTEGER NOT NULL,
  gender     VARCHAR(20) NOT NULL DEFAULT 'UNKNOWN'   -- NEW
);
```

#### MySQL (`src/main/resources/db/mysql/schema.sql`)
```sql
CREATE TABLE IF NOT EXISTS pets (
  id INT(4) UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(30),
  birth_date DATE,
  type_id INT(4) UNSIGNED NOT NULL,
  owner_id INT(4) UNSIGNED NOT NULL,
  gender VARCHAR(20) NOT NULL DEFAULT 'UNKNOWN',      -- NEW
  INDEX(name),
  FOREIGN KEY (owner_id) REFERENCES owners(id),
  FOREIGN KEY (type_id) REFERENCES types(id)
) engine=InnoDB;
```

#### PostgreSQL (`src/main/resources/db/postgresql/schema.sql`)
```sql
CREATE TABLE IF NOT EXISTS pets (
  id SERIAL,
  name VARCHAR(30),
  birth_date DATE,
  type_id INT NOT NULL,
  owner_id INT NOT NULL,
  gender VARCHAR(20) NOT NULL DEFAULT 'UNKNOWN',      -- NEW
  FOREIGN KEY (owner_id) REFERENCES owners(id),
  FOREIGN KEY (type_id) REFERENCES types(id),
  CONSTRAINT pk_pets PRIMARY KEY (id)
);
```

### `data.sql` seed data — all four databases

All existing `INSERT INTO pets` statements must include the `gender` column with value `'UNKNOWN'` to satisfy the `NOT NULL` constraint and the migration requirement (FR-007).

## Relationships Summary

```
Pet (entity)
 ├── gender : Gender [MALE | FEMALE | UNKNOWN]   ← NEW
 ├── name : String
 ├── birthDate : LocalDate
 ├── type : PetType  (ManyToOne → types table)
 ├── owner : Owner   (ManyToOne → owners table)
 └── visits : Set<Visit>  (OneToMany)
```

No new foreign keys or join tables. The `gender` column is a simple scalar on the `pets` table.
